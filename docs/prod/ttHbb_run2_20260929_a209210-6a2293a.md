## Notes

Run 2 ttHbb, stitched ttbar (TTTo*_stitched incl. TTbb). Phases B, C, C4, D, F (A skipped: picoAODs from algomez/XX4b/2024_v2). F.1/C.4 use this roast's own JCM, FvT and SvB (captured config overrides; the source analysis_ttHbb.yml keeps the static ttHbb_stitched friends for CI).

**Results.** JCM fit (SB): χ²/ndf = 20.2/12, closure 1.000 ± 0.003. F.1 vs C.4 cutflow crosscheck: PASS (210 compared, 0 differ; blinded 4b data ignored). Combine (blinded, Asimov): expected significance 7.5σ / limit 0.26 × SM for `ttHbb`; systematics are only the data-driven background shape basis (borrowed HIG-24-010 zz closure), lumi and BR, i.e. effectively stat-only.

**Known issues.**
- The C.4 and F.1 closure cutflow tables (`cutflow_FvT_closure.html`, `cutflow_closure_ttHbb.html`) show tt 4b = 0: `processor_ttHbb.fill_detailed_cutflows` does not call `_fill_ttbar_detailed_cutflows`, so the `TTbar_from_d3` cutflow entries are empty. The histograms (plots, Combine `tt` template) are unaffected. Fixed upstream after this roast; not rerun. Use [cutflow_FvT_closure_MCttbar](https://johnda.web.cern.ch/johnda/HH4b/prod/ttHbb_run2_20260929_a209210-6a2293a/output/ttHbb/FvT_closure/cutflow_FvT_closure_MCttbar.html) (4b ttbar from MC, made by hand): SR 1.072, SB 1.053.
- The B.1 closure table (`computeJCM/cutflow_wJCM.html`) also shows tt = 0: the closure-table rule hardcodes non-stitched ttbar names. Hand-regenerated with the stitched names: [cutflow_wJCM_stitchedttbar](https://johnda.web.cern.ch/johnda/HH4b/prod/ttHbb_run2_20260929_a209210-6a2293a/output/ttHbb/computeJCM/cutflow_wJCM_stitchedttbar.html) (SB 1.000, SR 1.339).
- B.1 JCM fit ran with `--data4bName data` (jcm_extra_arguments): make_jcm_weights.py replaces data4bName with the `-w` label when it contains "v".
- This roast ran with dump-only cutflow references; its B.1, C.4 and F.1 cutflows are now blessed as `known_fullCounts_{JCM_NoJCM,JCM_wJCM,FvT_closure}_ttHbb.yml` and `known_fullCounts_ttHbb_run2.yml` (coffea4bees ae755c04d). C.4/F.1 depend on this roast's FvT/SvB training, so later roasts only flag mismatches there (`known_counts_fatal: false`, coffea4bees 64de10196); B.1 stays fatal.
